# 07. 휴대폰 코드 가이드

## 읽기와 근거 확인

이 가이드는 [휴대폰 계약](../AGENTS.md)의 코드 탐색 지도다. 각 행의 소유 경로·대표 구현·테스트가 근거 경로다. 요청과 관련된 경로의 Git 변경을 확인하고 현재 호출자·호출 대상·공유 소유자로 이어서 읽는다.

## Conventions and Canonical Examples

건강 연동의 첫 안내는 [HealthPermissionModal](../src/features/healthImport/components/HealthPermissionModal.tsx)과 [useHealthPermissionModal](../src/features/healthImport/hooks/useHealthPermissionModal.ts)이 소유한다. `계속`만 시스템 요청으로 연결하고 안내 닫기로 완료 처리하지 않는다. iOS HealthKit은 읽기만 요청하며, 읽기 허용 여부를 앱에서 판별할 수 없으므로 권한 설정의 `건강 앱에서 확인` 상태와 앱의 가져오기 스위치를 구분한다. 위치·동작의 최초 시스템 요청과 거부 뒤 설정 복구 안내는 별도 기존 소유자를 유지한다.

HealthKit을 읽기만 요청하더라도 App Store 업로드 검증은 `NSHealthUpdateUsageDescription`을 요구한다(90683). Info.plist와 ko/ja 용도 문자열에 두 Health 설명 키를 유지하고, 쓰기 설명에서도 현재 읽기만 하며 저장·수정하지 않는 동작을 정확히 명시한다.

## Dependency and Ownership

`app/`의 진입은 기능 화면/provider로, 기능은 기존 service·query·공유 UI·유틸리티로 연결된다. 인증·캐시·저장·전송의 공통 동작은 위 소유 구현을 사용한다. 토큰 저장의 호출 경계는 `tokenStorage`, 캐시 키는 공통 또는 해당 기능의 기존 정의를 따른다. watchOS·Wear OS 작업은 [watchOS 가이드](../watchos/docs/07-codebase-guide.md)와 [Wear OS 가이드](../wearos/docs/07-codebase-guide.md)로 이어진다.

### 알림 표시·설정·복귀 경계

- [NotificationViews](../src/features/notifications/views/NotificationViews.tsx)는 알림함 focus 재조회와 성공한 읽음 응답의 사용자별 목록 캐시 반영을 소유한다. 기존 항목이 있어도 갱신 실패를 안내하며 404·잘못된 ID와 일시 조회 오류를 구분한다. 러닝 CTA는 `dismissTo`로 기존 탭에 복귀한다.
- 설정은 변경한 필드만 PATCH하고 전체 응답을 반영한다. OS 권한은 focus·active에서 별도 조회하며, 기기 차단 상태는 사용자의 서버 수신 선호값과 구분한다. [pushRegistration](../src/features/notifications/services/pushRegistration.ts)은 실패한 등록을 전경의 같은 세션에서 최대 세 번 재시도하고 새 sync·로그아웃·백그라운드에서 예약을 취소한다.
- [AuthProvider](../src/providers/AuthProvider.tsx)가 [appStore](../src/stores/app/appStore.ts)의 세션별 초기 이동 완료를 기록한다. [NotificationProvider](../src/features/notifications/NotificationProvider.tsx)는 현재 세션·약관·OTA 준비 후 푸시를 소비한다. `recipientUserId`가 현재 사용자와 일치하는 원문만 전경에 표시하고, 이전 ID-only payload의 탭은 서버 open으로 소유권을 확인한다. 두 [리그 결과 route](../app/league)는 focused 동안만 Android 뒤로가기를 차단한다.
