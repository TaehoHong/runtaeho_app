- 원래 분석을 방어하는 대신 각 주장에 반하는 호출자·가드·복구 owner·설치 라이브러리·서버 계약을 먼저 찾았다.

- 실제 코드의 메모리 변환, 실제 React/QueryClient/서비스를 연결한 격리 진단, 설치 router reducer 등을 사용했다. 외부 transport/native/router 경계는 제어했다. 강제 세션 주입은 메커니즘 증거로만 취급하고 사용자 UI 도달성의 증거로 간주하지 않았다.

## 진단 근거와 한계

- 시작/러닝: 실제 초기화 callback의 readiness, 실제 Pedometer 계산, 공유/완료 handler의 응답 순서, 실제 mutation/cache 경계를 메모리에서 실행했다. 기기·실제 계정 전환은 실행하지 않았다.
- 통계/리그: 실제 memo chart와 VM/query를 실행해 늦은 next 및 인접 캐시 문제를 확인했다. 실제 리그 hook/API 경계에서 늦은 성공/실패 쓰기를 확인하고, 두 실제 화면의 effect와 설치 stack reducer를 실행했다.
- 인증/설정: 실제 callback/서비스/설치 SDK translator를 실행해 refresh resolve, 표시 역전, 부분 성공 오류, Google 취소, OTA 재검사를 확인했다. 강제 B 상태는 UI 재현이라고 보고하지 않았다.
- 폼/신발/지원: caller·modal·버튼·설치 router·서버 DTO/repository를 정적으로 대조했다. 이 범위의 실제 UI/DB 실행은 하지 않았다.
- Unity/공유: 실제 VM/Preview/bootstrap/readiness/queue와 composed hook, 실제 Screen/restore owner를 연결했다. native 적용·이미지 변환/capture는 doubles로 제어했다. 임시 probe는 제거했다.
- 알림/Garmin: 실제 화면/service/query 설정과 React 19.1·TanStack 5.90.19를 실행했다. 7개 assertion 통과와 정상 종료 코드 0을 확인했으며, component unmount 후 QueryClient.clear로 정리했다.
- 전체 앱을 실행한 재현, 운영 로그·발생률, 실제 네이티브 화면·gesture·OAuth·Health 권한, 실서버 mutation, release 성능·캐시 용량 측정은 하지 않았다. P2 유지 항목도 각각 명시한 전제와 관측 수준까지만 확인했다.

## 후속 작업의 기준

미수정 문제를 구현하기 전에 해당 화면의 실제 조건을 보호하는 최소 회귀를 선정한다. 현재 P2 유지 항목은 검토 후보이며 이 재리뷰 자체가 제품 코드 쓰기 승인은 아니다. 보류 항목은 먼저 UI/기기 또는 측정 근거를 확보하고, 철회한 주장은 새 근거 없이 결함 목록으로 되돌리지 않는다. 방어 코드의 부재나 요청 수만으로 결함을 새로 만들지 않는다.
